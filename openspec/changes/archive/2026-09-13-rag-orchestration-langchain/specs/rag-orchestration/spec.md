# rag-orchestration Specification

## Purpose

为 RAG 问答链路提供编排基座的行为契约：观测（tracing）可开关且故障不伤业务链路、数据出网受控、检索阶段完成权限过滤、权限真相源与 prompt 产物归属明确。本 capability 约束的是"任何 RAG 链路实现都必须满足的横切行为"，不约束具体问答端点或入库流程（由后续 capability 承载）。

## ADDED Requirements

### Requirement: 观测追踪默认关闭且可多粒度开启

系统 SHALL 提供可配置的链路观测（tracing）能力，且观测 MUST 默认关闭；关闭时系统 MUST NOT 向任何观测后端发送数据。观测 MUST 支持两级开启粒度：进程级（配置项控制整个应用实例）与请求级（仅对特定请求开启，如管理员调试会话）。请求级开关 MUST 能覆盖进程级默认值。

#### Scenario: 缺省启动时观测关闭

- **WHEN** 环境中未提供任何观测相关配置并启动应用
- **THEN** 应用正常启动，问答链路正常工作，且不产生任何指向观测后端的网络请求

#### Scenario: 进程级开启

- **WHEN** 通过环境变量开启进程级观测后处理一次问答请求
- **THEN** 该请求产生的链路追踪数据被上报到所配置的观测后端

#### Scenario: 请求级覆盖

- **WHEN** 进程级观测处于关闭状态，但某一请求被标记为"调试追踪"
- **THEN** 仅该请求的链路数据被上报，其余并发请求不产生上报

### Requirement: 观测上报失败不得影响业务链路

观测 MUST 为非生产链路必需依赖。当观测已开启但其后端不可达、认证失败或网络黑洞时，系统 MUST 以 fail-open 方式继续正常处理业务请求：不产生错误响应、不中断流式输出、不因上报阻塞或重试导致业务延迟显著劣化。观测相关异常 MUST 被记录到应用日志（含 request_id），且 MUST NOT 传播为用户可见错误。

#### Scenario: 观测后端不可达时问答仍成功

- **WHEN** 观测已开启且观测后端完全不可达（连接黑洞）时处理一次问答请求
- **THEN** 请求正常返回完整答案，HTTP 状态与响应内容与观测关闭时一致，且日志中出现观测失败记录

#### Scenario: 观测后端认证失效时问答仍成功

- **WHEN** 观测凭证无效或过期时处理一次问答请求
- **THEN** 问答链路不受影响，不返回 5xx，答案内容完整

### Requirement: 观测数据出网目标受配置约束

系统 SHALL 通过配置指定观测数据的上报目标地址。链路追踪中包含的用户问题、召回内容等业务数据 MUST ONLY 发往配置指定的目标；未配置目标时观测 MUST 视为关闭。该约束使部署方可将观测指向自托管后端（内网），而非固定绑定某个 SaaS 服务。

#### Scenario: 指向自托管后端

- **WHEN** 观测目标配置为企业内网自托管地址并开启观测
- **THEN** 追踪数据仅发往该内网地址

#### Scenario: 业务文档不出现在未授权目的地

- **WHEN** 观测处于关闭状态
- **THEN** 用户问题与召回内容不离开本进程（不出现在任何外部请求中）

### Requirement: 检索阶段完成知识库级权限过滤

检索组件 SHALL 在向量库检索阶段（查询请求内）完成知识库级授权过滤：调用方传入用户被授权的知识库标识集合，检索查询 MUST 携带该集合作为服务端过滤条件，由向量库在扫描阶段剔除未授权知识库的内容。系统 MUST NOT 采用"先全量检索、应用层再过滤"的实现方式。检索结果 MUST NOT 包含未授权知识库的任何内容片段。

#### Scenario: 未授权库内容不可见

- **WHEN** 用户仅被授权知识库 A，而知识库 B 中存在与查询语义匹配的内容
- **THEN** 检索结果中不包含知识库 B 的任何内容片段，所有结果均来自知识库 A

#### Scenario: 过滤在检索查询中生效

- **WHEN** 检索组件执行一次带授权集合的查询
- **THEN** 发往向量库的查询请求中包含基于该集合的过滤条件（而非检索后由应用侧丢弃）

#### Scenario: 授权集合为空

- **WHEN** 用户不持有任何知识库授权并发起检索
- **THEN** 检索直接返回空结果，不执行向量库查询

### Requirement: 授权数据以业务数据库为唯一真相源

用户与知识库的授权关系 MUST 以业务 MySQL 中的授权记录为唯一真相源。检索所使用的授权集合 MUST 在每次检索时从授权记录解析得出；授权撤销后，该用户后续检索 MUST NOT 再返回被撤销知识库的内容。若实现引入授权缓存以降低查询开销，撤销后的生效延迟 MUST 为有界值且可配置，默认配置下 MUST 不超过 5 秒。

#### Scenario: 授权即时生效

- **WHEN** 管理员为用户新增知识库 C 的授权后，该用户立即发起检索
- **THEN** 知识库 C 的内容进入该用户的检索范围

#### Scenario: 撤销授权后不可再检索

- **WHEN** 管理员撤销用户对知识库 A 的授权后，该用户再次检索
- **THEN** 检索结果中不再出现知识库 A 的内容片段（在配置的生效延迟内收敛）

### Requirement: 生成用提示词模板入仓管理

生成答案所用的提示词模板 MUST 以源码或配置文件形式存在于仓库中，纳入版本管理与代码评审；系统 MUST NOT 在运行时从外部服务（如在线提示词仓库）拉取提示词模板。提示词模板内容变更 MUST 通过代码变更流程（含评审）生效。

#### Scenario: 无外网提示词服务时链路可用

- **WHEN** 除模型 API 外所有外网均不可达时处理一次问答请求
- **THEN** 生成链路使用仓库内置模板正常完成

#### Scenario: 模板变更可追溯

- **WHEN** 查看任一提示词模板的修改历史
- **THEN** 可在仓库版本历史中追溯每次变更及其评审记录
